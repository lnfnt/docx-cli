# CONTRIBUTING — docx-cli

## Process
1. Issue/задача с вектором воспроизведения (для изменений сканера/валидатора — синтетический
   docx или spec-минимум, живые документы дел — никогда).
2. Тест сначала (RED) с ссылкой наFinding-номер, реализация (GREEN).
3. `python -m pytest -q -o addopts=''` — зелёный; старые тесты не редактируются без
   обоснования в PR (история контрактов пинится).
4. Envelope-вывод CLI — стабильный JSON; exit-коды: 0 ok / 1 бизнес-отказ / 2 usage.
5. DCO: коммит с `Signed-off-by:` — вклад передаётся под Apache-2.0 (патент-грант включительно);
   отправляя patch, вы подтверждаете права на него и согласны с лицензией репозитория.

## Release discipline
- Именованный артефакт релиза не перезаписывается; новая версия — новые dist-файлы + SHA256SUMS +
  detached GPG-подпись release-ключом; `doctor --verify-signature` обязан быть ok до анонса.
- Изменения сканера безопасности требуют прогона векторного набора (tests/test_v0*_*.py)
  и свежей установки в чистом venv из allowlist-архива.
- docx bus-free: пакет не должен вызывать шину/a2a/сеть; интеграция — только печатью готовых команд.

## What we don't take
- Юридические заключения/дисклеймеры в код (контент — зона правоприменителя).
- Фикстуры с реальными сторонами, номерами дел, ПДн.
