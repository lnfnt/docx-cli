# Архитектура docx-cli

## Структура пакета

```
docx_cli/
  __init__.py      # Публичный API: build_document, DocSpec, validate_document
  __main__.py      # python -m docx_cli
  cli.py           # argparse CLI и единый JSON-конверт
  spec.py          # DocSpec (pydantic), профили, defaults
  builder.py       # Ядро генерации документа через python-docx
  blocks.py        # Рендеринг каждого типа блока
  validate.py      # Встроенный валидатор результата
  errors.py        # Исключения: SpecError, BuildError, ValidationError
```

## Поток данных

```
spec.json -> spec.py (DocSpec) -> builder.py -> blocks.py -> .docx
                                      |
                                      v
                                validate.py -> JSON envelope
```

1. CLI загружает `spec.json` и парсит его через `DocSpec.from_dict`.
2. При любом нарушении схемы выбрасывается `SpecError` — fail-closed, никаких догадок.
3. `builder.py` создаёт документ, настраивает секцию (A4, поля) и вызывает рендереры блоков.
4. После сохранения файл немедленно открывается `validate.py`.
5. Если валидация находит ошибки, частичный файл удаляется, возвращается `ok: false`.
6. Все команды возвращают единый JSON-конверт.

## Профили

Профиль — это набор параметров оформления. Реализованы:

- `gost` — юридический стандарт, поля 3.0/1.5/2.0/2.0, интервал 1.5, отступ 1.25 см.
- `compact` — уменьшенные поля и интервал 1.15.
- `court` — процессуальный стандарт: 14 pt везде, интервал 1.0 (или 1.15), те же поля, шапка как блок с `left_indent = 7.0 см`, висячий отступ списков, текстовый формат подписи.

Профиль не задаёт содержание, только макет.

## Ветвление профилей

- `spec.py` валидирует имя профиля и специфичные параметры (`line_spacing`, диапазон `header.left_indent_cm`).
- `builder.py` создаёт объект `Profile(name, line_spacing=...)`; настройки документа и рендер блоков берутся из профиля.
- `blocks.py` ветвит рендеринг: шапка `court` верстается через `left_indent` и LEFT, подпись `court` по умолчанию текстом, списки получают висячий отступ для всех профилей.
- `validate.py` ветвит проверки: для `court` дополнительно контролируются 14 pt везде, геометрия шапки, формат `pleading_marker` и висячий отступ списков; для `gost` остаются прежние правила (12 pt, 1.5, JUSTIFY).

## Валидация

Валидатор переоткрывает собранный `.docx` и проверяет:

- целостность zip-пакета и разрешение связей;
- поля секции;
- шрифт и размеры run'ов с учётом профиля;
- межстрочный интервал и абзацный отступ тела;
- для списков — висячий отступ (`left_indent = 1.25 см`, `first_line_indent = -0.75 см`);
- для `court` — геометрию шапки и формат маркера `pleading_marker`;
- отсутствие en-dash;
- отсутствие `ё` вне реквизитов (при `no_yo`);
- последовательность нумерации.

## Контракт ошибок

- `SpecError` — входные данные не соответствуют схеме.
- `BuildError` — сбой генерации.
- `ValidationError` — результат не прошёл проверки (на практике обрабатывается через envelope).
