# Ограничения docx-cli

## Что пакет не делает

- Не проверяет юридическое содержание и не применяет нормы права.
- Не парсит PDF, сканы или изображения.
- Не конвертирует `.docx` в PDF (проверяет наличие зависимостей через `doctor`, но не вызывает LibreOffice).
- Не редактирует существующие `.docx` — только генерация с нуля.
- Не придумывает факты: пробелы должны быть явными плейсхолдерами `[УКАЗАТЬ ...]`.

## Известные ограничения реализации

- Inline markdown поддерживает только `**жирный**` и `*курсив*`; вложенная разметка и ссылки не реализованы.
- Нумерованные списки формируются вручную (`1.`, `2.`); автоматическая нумерация Word не используется.
- Профили: `gost`, `compact`, `court`.
- В standalone-режиме `validate <file.docx>` нет доступа к исходному spec, поэтому для проверки `ё` отсутствует whitelist реквизитов.
- Плейсхолдеры всегда порождают предупреждение, но не ошибку.

## Границы надежности

- Все ГОСТ-параметры проверяются обратным чтением сгенерированного файла, а не «на слово».
- При ошибке валидации частичный файл удаляется.
- Пакет fail-closed: любая неизвестная схеме spec-величина отклоняется.
