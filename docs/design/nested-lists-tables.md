# B-10: вложенные списки и pipe-таблицы в md-конвертере — дизайн

> Статус: утверждён до реализации (B-10 boundary). Реализация: `docx_cli/md_court.py`.
> Версия: v0.1.0 (§2 task-doc).

## 1. Вложенные списки

### 1.1 Идентификация уровня
- Список-прогон (run) = подряд идущие строки, matching `^([ \t]*)([-*]|\d+[.)])\s+`.
- Табы разворачиваются в 4 пробела до вычисления отступа.
- Шаг отступа `unit` = минимальный положительный отступ внутри run (типично 2 или 4);
  если положительного отступа нет — `unit = 2`, все элементы level 1.
- `level = indent // unit + 1` (т.е. 0 отступ → level 1; GFM-терпимость: 3 пробела при
  unit=2 всё ещё level 2).
- `level > 4` — НЕ рендерится: в `report` строка-маркер
  `{type: "skipped_construct", construct: "list_depth_gt4", line: <номер>, text: ...}`.
  Молчаливого проглатывания нет — тот же принцип честности, что у skip-канала V-02
  (`check_skipped` в валидаторе).

### 1.2 Смешанные ordered/unordered
- Соседние маркеры `-`/`*`/`N.`/`N)` в одном run образуют один список; тип маркера
  учитывается per item (bullet vs numbered), счётчик нумерации ведётся отдельно на
  каждом уровне и НЕ сбрасывается при чередовании ul/ol на том же уровне
  («нумерация продолжается по level+marker type»). Новый run — новый счётчик.

### 1.3 DOCX-рендер — решение по спорным пунктам
- **Level 1 остаётся легаси-рендером** (висячий отступ left 1.25 см / first −0.75 см,
  без стиля) — иначе ломается пин «старый md байт-стабилен». Стили List Bullet/Number
  применяются только к level 2–4.
- Level 2/3: стили `List Bullet 2/3`, `List Number 2/3` (есть в дефолтном шаблоне
  python-docx 1.2.0). Стилей `… 1` и `… 4` в шаблоне НЕТ — это ожидаемо.
- Level 4 (стиль отсутствует) и любой уровень, если стиль не найден в конкретном
  шаблоне: **manual fallback** — left = 1.25 + 0.75·(level−1) см, first = −0.75 см,
  без падения. Для numbered fallback-элементов в текст пишется литеральный номер
  `N. ` из парсерного счётчика (автонумерации стиля нет — номер должен быть видим).
- В style-mode номера НЕ пишутся литерально (стиль автонумерует; двойная нумерация —
  дефект). Следствие для round-trip: уровень восстанавливается по имени стиля,
  литеральные цифры — только в fallback-режиме.
- Bullet-маркеры (`-`/`*`) съедаются парсером и не печатаются литерально (как в v0.9).

### 1.4 Round-trip контракт
Извлечённая структура: порядок параграфов; для списков — (level, marker type);
уровень из style-имени `List (Bullet|Number) N`, иначе из полосы left-отступа.

## 2. GFM pipe-таблицы

### 2.1 Парсинг
- Таблица = строка-заголовок с `|`, следующая строка-разделитель (столбцы из `-`,
  `:`, пробелов; выравнивание `:---`, `---:`, `:---:`), далее строки с `|`.
- Разделители внешнего вида `| a | b |` и `a | b` (внешние pipes необязательны).
- Разбиение ячеек по НЕэкранированным `|`; `\|` → литеральная `|` в тексте ячейки.
- Таблицы распознаются только в зоне тела (после титула). В шапке-реквизитах pipes
  остаются легаси-текстом (не бывает табличной шапки в процессуальной реквизитке).
- Пустое тело (только заголовок+разделитель) = валидная таблица из 1 строки
  («header-only»). Короткая строка дополняется пустыми ячейками, лишние ячейки
  отбрасываются — с маркером в `report` (честно, см. 2.3).

### 2.2 DOCX-рендер
- Стиль таблицы `Table Grid` (есть в шаблоне), autofit (ширины auto).
- Строка заголовка: bold-флаг на runs + `tblHeader` (повтор заголовка при переносе).
- Выравнивание колонок переносится в каждую ячейку: `:---`→LEFT (дефолт),
  `---:`→RIGHT, `:---:`→CENTER. Justify в таблицах md не используется.
- Inline-конверт ячеек: `**bold**`, `_italic_`, `` `code` `` (шрифт Courier New),
  `<u>underline</u>`; en-dash нормализуется тем же `_normalize_dashes`.
  Отдельный конвертер для ячеек: обычные параграфы тела используют прежний
  `_add_inline_runs` без backtick-ветки — регресс-пин не двигается.

### 2.3 Skip-канал (обновление спецификации V-02)
Канал честных пропусков `report` расширен записями
`{type: "skipped_construct", construct, line, text, reason}`:

| Конструкция | v0.9 (было) | v0.10 (стало) |
|---|---|---|
| Вложенные списки levels 2–3 | сплющивались в level 1 | конвертируются (стили) |
| level 4 | сплющивалась | конвертируется (manual fallback) |
| level ≥5 | сплющивалась | skip-маркер `list_depth_gt4` |
| pipe-таблицы | печатались литеральными `|` | конвертируются в Table Grid |
| `\|` escape | литерал с обратным слэшем | экранированная pipe в ячейке |
| блок внутри ячейки (`>…`, список) | литеральный текст | skip-маркер `block_in_cell` (вся строка) |
| списки/таблицы внутри ячеек | — | НЕ поддерживаем, честно (skip-маркер) |
| mismatch ширины строк | литеральный текст | pad/truncate + skip-маркер `row_width_mismatch` |

Списки внутри ячеек сознательно НЕ поддерживаются: python-docx позволяет, но
round-trip структура перестаёт быть однозначной, а в процессуальных документах
такие конструкции — редкость хуже битой вёрстки. Строка с любой блочной
конструкцией в ячейке пропускается целиком и маркируется — не рендерится криво.

## 4. Обратная совместимость
- md без таблиц и вложенностей: структура вывода и `report` совпадают с v0.9
  (пин: `tests/fixtures/v0100_legacy_md.json`, снят с кода v0.9.0 ДО рефакторинга).
- Заголовки, ПРОШУ:, ПРОЕКТ, шапка-реквизиты, висячие отступы level 1, dash-фикс —
  прежние ветки без изменений.
- `md_build` contract (ключи конверта) не меняется; `report`/`fixes` пополняются
  skip-маркерами только там, где раньше молча ломалась структура.


## Post-design fix координатора (24.10, контроль волны)
1. `code` в ячейках рендерится **Times New Roman**, не Courier: standalone-валидатор
   бракует любой иной font_name (`font_name: run uses 'Courier New'`). Бэктик-синтаксис
   сохранён, моноширинная косметика принесена валидность-контракту.
2. Ячейки штамуются пост-проходом `_stamp_table_cells`: размер = `cell_font_size_pt`
   угаданного валидатором профиля (gost→11, court→14). До фикса таблицы md-build
   падали на собственной validate (cell_font_size).
3. Вложенные списки (List Bullet/Number, legacy level-1 с левым отступом) исключены
   из body-проверок классификатором validate (role=other, reason=list_paragraph) —
   по той же логике, что уже исключает "N. " и hanging-indent списки.
